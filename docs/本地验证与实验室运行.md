# 本地验证与实验室运行

更新：2026-10-28。

## 已实际执行的本地验证

| 检查 | 结果与范围 |
| --- | --- |
| 完整 RTL + NumPy | 6 种配置，每种 6 组输入，共 36 组；另每配置执行一次复位中断后重跑；所有阶段读回共比较 94,038 个值，通过 |
| 独立 Softmax RTL | N=1、3、64，每种 67 行，合计 201 行、4556 个概率值；逐值匹配定点 Golden，通过 |
| 指数 LUT RTL | 每次独立测试遍历全部 256 个地址，逐值匹配指数公式生成值，通过 |
| Softmax 浮点参考 | 1290 行量化 logits 上，定点概率相对浮点 Softmax 的最大绝对误差约 5.4087e-5；不代表模型端到端精度 |
| Yosys 结构检查 | 默认配置：层次、进程转换、驱动检查、无推断锁存器，通过；没有做工艺映射或 PPA 测量 |

端到端测试覆盖：全零、单位投影/FFN 权重、INT8 极值、三组固定种子随机数据；比较 Y、Q、K、V、S、P、Context、H 全部元素。每组测试还尝试忙时启动/写请求，检查请求被忽略、done 单拍、精确周期数；每个配置最后检查中途复位后重算。

配置顺序为 (N,D,F,LANES)：

```text
(1, 1, 1, 2)
(3, 5, 7, 2)
(4, 8, 16, 2)
(4, 8, 16, 1)
(8, 16, 32, 4)
(64, 8, 16, 2)
```

默认 (4,8,16,2) 计算 1080 拍；同尺寸 LANES=1 时为 2104 拍。它们是本地仿真测得的周期，不是 DC/ICC 测得的频率或吞吐量。

## 本地复现

在 `D:\class\EDA\eda_t2_accelerator` 打开终端：

```powershell
python scripts/run_tests.py
python scripts/test_softmax.py
python scripts/synth_check.py
```

依赖：Python + NumPy、Icarus（iverilog/vvp）；结构检查额外需要 Yosys。优先读取 `EDA_OSS_CAD_SUITE`，然后本机已安装的 `D:\eda-tools\oss-cad-suite`，最后 PATH。Linux 可将工具加入 PATH。脚本没有安装依赖或修改系统配置。

常用输出：

```text
build/test_summary.json
build/softmax_summary.json
build/synth_check/summary.json
build/synth_check/yosys.log
build/n4_d8_f16_p2/simulation.log
build/n4_d8_f16_p2/wave.vcd
```

`build/` 是可重建目录，重复运行会更新同配置的测试输出；需要留档时先复制。实验室入口采用新的时间戳目录，避免覆盖原结果。

如需重新生成 LUT：`python scripts/generate_lut.py`，修改 LUT 后重新执行测试。

若只需要生成测试向量、暂不运行仿真：

```sh
python scripts/run_tests.py --generate-only
python scripts/run_tests.py --generate-only --full
```

这两个命令的清单写入 `build/vector_manifest.json`，明确标注 GENERATED_NOT_SIMULATED，不覆盖本地回归 PASS 汇总。`--full` 的大维度仿真建议在实验室 VCS 单独执行，避免本机编译超时。

## 实验室 VCS：默认配置可以先跑

把整个 `eda_t2_accelerator` 目录复制到实验室。默认测试所需 `tests/default/` 已附带，不依赖实验室 Python 或 NumPy；不要只复制 RTL。

初始化实验室工具环境后，在项目根目录运行：

```sh
bash lab/run_vcs.sh
```

预期生成新的 `lab_runs/vcs_年月日_时分秒/`：

- `compile.log`：VCS 编译日志。
- `simulation.log`：六组输入及复位重跑结果，最终应含 `ALL_PASS checked=1792 reset_recovery=PASS`。
- `wave.vcd`：默认配置端口、状态与部分内部信号的波形。

这是预期结果，不是声称 VCS 已执行通过。查看器由实验室实际工具决定；选择 clk/rst_n/start/busy/done/cycles、state/phase、rd_bank/rd_addr/rd_data 等信号，按手册截图。

如要运行其他配置：在对应 `build/n*_d*_f*_p*/` 内放入 input.hex、expected.hex，再用 VCS 编译该目录 tb.sv 和同一份 RTL。尺寸与 SCALE 参数已写在生成的 Testbench 实例中；不要仅换输入文件却保留旧尺寸实例。

## 实验室 DC：默认配置入口

目录相邻放置：

```text
你的实验室工作目录/
  sm2/
    ref/db/sc_max.db
    ...
  eda_t2_accelerator/
    rtl/
    lab/
    ...
```

在新项目根目录执行：

```sh
mkdir -p logs
set -o pipefail
dc_shell -f lab/dc_synth.tcl 2>&1 | tee logs/dc_console.log
```

上述命令按 Bash 编写。若使用 csh，先进入 Bash 再执行。库目录不相邻时，在 Bash 设置 `export T2_REF=/你的实际路径/sm2/ref`。目标周期默认 50.0；需要更改时设置 `export T2_PERIOD=50.0`。数值单位必须结合工具 `reports/units.rpt` 核查，当前意图为 ns。

脚本综合默认 N=4,D=8,F=16,LANES=2，**不是最大配置**；输出在新的 `lab_runs/dc_年月日_时分秒/`。后续综合不同配置须同步修改 elaborate 参数和记录 SCALE、移位、尺寸，不要把小规模结果写成大规模结果。

首先带回完整 `logs/dc_console.log` 和这次运行目录。优先查看：

1. 是否有 Error、未解析实例、锁存器、不受约束路径、库读取失败或许可证错误。
2. `run_scope.txt`、`reports/units.rpt` 和 `reports/clocks.rpt` 是否符合本次配置。
3. 面积、时序、约束、功耗报告是否实际生成；路径的 slack 和关键点是否可解释。

输出包含 mapped.ddc、mapped.v、SDC、SVF。无扫描链插入；功耗为未加载 SAIF/VCD 的估算。复位路径被排除，复位释放需要外部同步，不能把该结果宣称为复位 recovery/removal 已验证。

脚本尚未经过实验室 DC 验证。若工具不支持命令或出现许可/库问题，保留第一处错误上下文和全日志；不能凭 shell 返回成功就判定综合成功。
